# readme-writer — 简洁、可验证的项目入口

README 是项目入口，不是完整手册、设计文档、变更日志或宣传页。读者应能快速回答：
这是什么、是否与我有关、怎样完成第一次成功使用。用最少内容把这三件事说清。

## 适用边界

- **创建**：仓库没有 README，或现有内容已无法修补时，从事实源生成最小完整版本。
- **改写**：保留仍正确且有用的内容，做最小范围调整；不借机重排无关章节。
- **审查**：用户只要求 review 时，先列影响最大的冗余、缺失和失实问题，再给精简
  结构；未经要求不直接重写。
- API 参考、架构细节、贡献者手册、教程、plan / report 和 changelog 各归其位；
  README 只摘要并链接，不复制正文。

## 写前事实核验

先读仓库再写。按任务需要核对入口代码、包清单、依赖锁定、CLI `--help`、配置样例、
测试 / 开发命令、已有 docs 与 LICENSE。现有 README 只能作为候选材料，不自动视为
权威源。

写前确定四件事：

1. 主要读者是谁；
2. 一句话如何准确说明项目用途；
3. 读者的第一次成功动作是什么；
4. 完成该动作真正需要哪些前置条件。

无法从仓库验证的功能、兼容性、性能、状态和命令不得编造。必要信息确实未知时，
明确缺口或省略，不用占位符、猜测和营销措辞填满版面。

## 最小结构

默认从以下骨架开始，按实际需要删减或扩展；标题不是配额：

```markdown
# <项目名>

<一句话说明它是什么、给谁用、解决什么问题。>

## Quick start
<必要前置条件、安装、最短可运行命令。>

## Usage
<一个最小真实示例，以及成功后应看到的行为。>
```

只有满足下列条件才新增可选章节：

- `Configuration`：首次核心使用必须配置，或存在少量高频配置；完整选项链接到参考文档。
- `Development`：仓库面向贡献者，且开发命令不能从标准清单直接看出。
- `Troubleshooting`：已有可复现的高频问题与确定解法，不为假想问题预写 FAQ。
- `Architecture`：理解顶层边界是正确使用的前提；只给概览并链接设计文档。
- `License`：给出许可证名和链接，不复制整份许可证正文。

按项目类型调整第一次成功动作：库给最小导入 / 调用示例；CLI 给一个代表性命令；
服务给启动命令与健康检查；应用给运行 / 构建入口；插件给支持宿主、安装和一次调用；
monorepo 只提供必要的包导航与作用域命令。

### Agent Skill / 插件仓库

当同一份 skill 或插件面向多个 coding agent 宿主，且源码地址可访问、目标 Agent 具备
安装能力时，优先提供可直接复制给 Agent 的跨宿主安装 Prompt，不在 README 逐项罗列
每个宿主的命令和用户目录。

- Prompt 写明权威源码 URL、安装范围、遵循当前宿主规范，以及完成后验证安装结果。
- 仓库同时支持“完整插件及全部 skills”和“单个 skill”且两种范围都对读者有用时，
  分别提供两个 Prompt；单 skill Prompt 可使用 `<skill-name>`，但必须紧接着说明替换
  方法并给出仓库中真实存在的 skill 示例。
- 目标 Agent 无安装能力、源码不可直接访问，或宿主确有不可省略的前置条件时，才提供
  已验证的宿主专属步骤；不宣称 Prompt 必然一键成功。

## 写作合同

- 开头直接给项目名和一句话定位，不先写背景故事、愿景或功能口号。
- 优先提供一条推荐路径。备选安装方式、完整参数、部署矩阵和高级配置移到专门文档。
- 命令应能从声明的工作目录直接复制执行；代码块标注语言，只解释非显然参数。
- 示例使用仓库中真实存在的名称、路径和接口，并保持为证明核心用途所需的最小规模。
- 段落一次只讲一件事；并列信息用列表，步骤有顺序时才用编号。
- 标题描述读者任务。短 README 不加目录；普通单组件 README 超过约 150 行时，
  必须执行一次拆分与链接审查，但不为追求行数删除必要信息。
- 使用项目既有语言和术语。除非仓库已形成维护惯例，不新增装饰性 emoji、徽章墙、
  大型目录树或截图集。
- 相同事实只保留一个权威表述。不要复述包清单、源码注释、完整 CLI 帮助、许可证、
  changelog、roadmap 或其它 docs 的正文。
- 不写“强大”“简单”“现代”“生产级”等无法验证的形容词；用具体能力和限制替代。
- README 按可能公开的内容处理，不写密钥、内部地址、个人绝对路径或不必要的环境信息。
- 不描述写作过程，不留下 TODO 或未解释的占位符。面向用户的可复制 Prompt 可保留一个
  有明确替换说明和真实示例的占位符。

## 完成前删减与验证

逐节检查：

1. 它是否帮助主要读者判断项目或完成核心任务？
2. 每个事实是否能指向当前仓库中的权威来源？
3. 内容是否与其它章节或文档重复？
4. 删除这一段是否会让核心路径失效或产生真实歧义？

不能帮助核心任务、缺少权威来源或只是重复，且删除后不会让核心路径失效或产生歧义
的内容，应删除或改为链接。随后验证相对链接、文件路径、命令名、参数和版本要求；
能在当前授权、成本与环境范围内安全快速执行的 Quick start 命令应实跑。不得为验证
README 擅自安装依赖或修改外部系统；无法实跑时如实说明未验证，不把静态阅读写成
运行成功。

完成标准：一句话定位准确；首次成功路径完整且最短；必要限制可见；无未核实断言；
所有可选章节都通过收录条件；README 与当前代码和清单一致。

## Red Flags

- 不读仓库就套万能模板；为了“看起来完整”添加空洞章节。
- Quick start 被背景、特性清单或架构说明挤到很后面。
- 同时罗列所有安装方式、参数、目录和内部实现，导致核心路径不可扫描。
- 多宿主 Agent Skill / 插件可以用一个安装 Prompt 覆盖，却仍逐项罗列宿主命令和目录。
- 用 README 代替 API 文档、贡献指南、设计文档、changelog 或 roadmap。
- 命令、链接、兼容性和功能状态未核实，却写成确定事实。
- 改一个局部说明时顺手格式化或重写整份 README。
