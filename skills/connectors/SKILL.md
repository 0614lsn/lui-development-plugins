# connectors — 外部资源通道注册表（模式 + 纪律）

每种外部资源走哪个通道、入口在哪、凭证从哪来、写操作要什么确认：一个项目只维护
一份权威注册表，本 skill 定义它的纪律与骨架。具体地址 / id / 凭证是项目数据，
由项目绑定在自有注册表中填写，不进入本通用文件。

## 通道纪律（与项目无关）

- **单一通道**：每种资源只认注册表声明的通道；绕过注册表直连，或另开未经声明的
  通道，都视为越界。
- **结构化资源不用 WebFetch**：有 MCP / CLI 入口的平台（文档库、模型库、代码协作
  平台），禁止退化为网页抓取。
- **凭证三不**：不进 git、不进日志、不进命令行明文。从环境变量或密钥管理读取，
  并在注册表写明凭证来源与加载方式（例如每个新 shell 需重新 source 的 env
  文件、远程机器上的 600 权限 env 文件）。
- **写操作确认**：创建 MR / issue、push、删除、流水线操作等写动作默认须人工确认，
  或落在 plan 预授权清单内按预授权执行；读操作不受限。
- **先 sanity 再批量**：批量上传 / 下载 / 迁移前跑秒级 sanity（凭证 + 网络 + 目标
  存在三者齐活）再开始，避免任务过半才 BLOCKED。不可逆批次操作（删除 / 迁移清单
  执行）单进程前台运行，同一清单任一时刻至多一个执行进程，不依赖后台探活判断
  进程已结束。
- **缺通道先提醒**：需要但未配置的 MCP / 凭证，开发前明确提醒用户配置，不硬来、
  不静默降级；这属于 LDP 的非闸门停止点「连接器缺配置」，缺口未补齐不进入
  阶段 1。

## 注册表骨架（项目按此填写）

```markdown
## 作用域（硬限制）
<允许操作的资源边界：哪些组织 / 项目 / bucket；明确不碰的清单。>

## 代码版本 — git
<各仓远端地址、主线分支、worktree 布局、push 纪律、大文件策略
（如模型本体不入 git，走对象存储 + manifest + sha256 回读校验）。>

## 协作层 — <MR / issue / CI 平台>
<通道类型（MCP / CLI）、可用操作、写操作确认级别、常用入口。>

## 文档 — <文档平台>
<通道、权威知识库位置、本地文档与线上权威源的更新方向。>

## 模型 / 数据集 — <模型平台>
<检索 / 元数据入口与文件传输入口分开声明，认证状态分别验证。>

## 对象存储 — <存储服务>
<bucket / region / 内外网 endpoint 差异、凭证来源、统一封装入口、数据布局约定、
回读校验要求。>

## 人工通道
<plan 闸门与终审升级人工走哪个宿主人机交互通道，见下节纪律。>

## 运行环境
<Python / Node 等运行时约定（如统一 uv、存量环境的读用限制）与特殊依赖位置。>
```

## 人工通道纪律

- 人机通道默认就是当前运行流程的宿主会话：工件在会话内呈现，用户在同一会话内
  回复裁决，不经其它自动通道代收。
- 消息已展示、通道已连接、Agent 已给出建议都不代表批准；必须收到明确的用户裁决
  原文并写回 plan / report / 记录，才能越过相应闸门。裁决含糊或未收到回复时
  保持停止。

## Red Flags

- 绕过注册表操作外部资源；对有 MCP / CLI 的结构化平台使用 WebFetch。
- 凭证或大文件本体提交进 git；token 出现在命令、日志或仓库中。
- 操作注册表作用域外的资源；未做 sanity 直接跑不可逆批次操作。
- 通道缺配置时不提醒用户、静默降级或硬闯。
